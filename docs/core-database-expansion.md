# Wineer 300 款核心酒库扩容方案

目标：从当前 100 款扩到 300 款，但不追求“全市场 SKU”。核心库只收适合推荐决策的代表性酒款，避免被开发酒、贴牌酒、礼盒规格 SKU 稀释质量。

## 分层目标

### 1. 核心推荐库：300 款

覆盖普通用户 80% 以上高频场景：自饮、朋友小聚、家庭聚餐、商务宴请、送礼、收藏入门。

建议结构：

| 维度 | 目标数量 | 说明 |
| --- | ---: | --- |
| 名酒/全国化品牌主线 | 120 | 茅台、五粮液、泸州老窖、汾酒、洋河、郎酒、习酒、剑南春等 |
| 区域强势品牌 | 80 | 安徽、江苏、山东、河南、陕西、贵州、四川、山西等区域名酒 |
| 口粮/光瓶/性价比 | 50 | 100 元内、100-200 元高频自饮款 |
| 送礼/商务高识别款 | 30 | 包装、品牌、流通性较强的中高端款 |
| 小众香型/老酒客风格 | 20 | 凤香、兼香、米香、董香、馥郁香等代表款 |

### 2. 增强推荐库：800–1500 款

用于 SEO、区域页、小众页、老酒客页，不一定全部进入默认推荐池。

### 3. 商品 SKU 库：1 万+ SKU

用于电商比价/返佣/价格监控。应和核心酒款建立映射，不建议直接混入推荐库。

300 款核心库建议：

| 价位档 | 数量 | 用途 |
| --- | ---: | --- |
| 口粮（<150） | 75 | 自饮、朋友小聚、入门 |
| 中端（150–600） | 135 | 家宴、朋友局、主流推荐核心 |
| 高端（600–1500） | 70 | 商务宴请、送礼 |
| 超高端（>1500） | 20 | 硬通货、收藏、强面子场景 |

## 数据准入标准

每款酒入库前至少满足以下一项：

1. 全国化或区域强品牌的稳定主线产品
2. 高频出现在商超/电商/酒类流通渠道
3. 在某个价格带或香型中有代表性
4. 用户决策场景明确：自饮、送礼、宴请、收藏等
5. 有足够公开资料可校验，不是纯营销定制款

谨慎收录：

- 贴牌/开发酒
- 只改包装但酒体不清晰的礼盒 SKU
- 价格大幅波动且渠道混乱的产品
- 来源不可验证的小众产品

## 建议新增字段

当前字段可继续保留，扩容前建议新增：

```json
{
  "source": ["公开渠道/品牌官网/主流电商/酒类媒体"],
  "lastChecked": "2026-08-11",
  "confidence": 0.8,
  "riskLevel": "low",
  "riskNotes": "假货风险/开发酒风险/价格波动提示",
  "buyingPriority": 4,
  "giftScore": 4,
  "selfDrinkScore": 5
}
```

字段含义：

- `confidence`：资料可信度，0–1
- `riskLevel`：low / medium / high
- `buyingPriority`：是否适合推荐购买，1–5
- `giftScore`：送礼适配度，1–5
- `selfDrinkScore`：自饮适配度，1–5

## 扩容流程

1. 列候选池：先做 500 款候选，不直接入库
2. 去重归并：合并同酒不同规格、礼盒、年份版
3. 人工筛选：保留 300 款核心款
4. 补字段：价格、香型、场景、风险提示、推荐理由
5. 跑校验：`python3 scripts/collect.py validate`
6. 抽样试推荐：覆盖 20 个典型用户画像
7. 发布前冻结版本：更新 `meta.version` 和 `meta.updated`

## 不建议现在做的事

- 不要直接抓全网 SKU 灌进推荐库
- 不要把电商礼盒规格当作独立酒款大量重复
- 不要为了数量牺牲避坑提示质量
- 不要在没有价格监控前承诺“最低价”
