# Wineer 微信小程序 MVP 设计

## 背景

Wineer 当前是一个纯静态 Web 应用。用户通过六个 0–10 的偏好维度描述预算、使用场景、酒劲承受、香味厚重、品牌面子和尝新程度，前端从白酒数据集中计算 Top 3 推荐，并展示推荐理由、避坑提示、分享入口和购买搜索入口。

本项目将在保留现有 Web 版本的同时，在 `wechat/` 下新增微信原生小程序。首版目标是实现与现有核心体验等价的 MVP，不引入登录、云开发、收藏、历史记录、运营后台或实时商品价格。

## 目标

- 在 `wineer/wechat/` 中提供可由微信开发者工具直接导入的原生小程序工程。
- 复用现有六维推荐规则和 `data/baijiu.json` 酒款数据。
- 确保 Web 和小程序使用同一份推荐核心，避免算法长期分叉。
- 支持首页年龄提示、六维问答、Top 3 结果、原生转发、分享海报、重新选择和复制购买搜索词。
- 使用占位 AppID，允许开发者后续替换为正式 AppID。
- 为推荐核心和数据生成流程建立自动化验证。

## 非目标

- 用户登录、手机号授权或微信账号绑定。
- 云开发、服务端 API、远程数据库和运营后台。
- 收藏、浏览历史和跨设备同步。
- 京东或其他电商小程序跳转。
- 联盟返佣、实时价格和库存查询。
- 广告、支付和订单能力。
- 将现有网站嵌入 `web-view`。
- Taro、uni-app 等跨端框架。

## 技术方案

采用微信原生小程序，并抽取环境无关的共享推荐核心：

```text
data/baijiu.json
       |
       +-- scripts/build.sh ----------------> web/data/baijiu.json
       |
       +-- 数据生成脚本 ---------------------> wechat/miniprogram/data/baijiu.js

shared/recommender.js
       |
       +-- web/app.js -----------------------> Web UI
       |
       +-- wechat/miniprogram/pages/* -------> 微信原生 UI
```

`shared/recommender.js` 不访问 DOM、`window`、`location`、`localStorage` 或 `wx`。它只接收普通 JavaScript 对象并返回普通 JavaScript 数据，使 Web、小程序和 Node 测试可以调用同一实现。

## 共享推荐核心

共享模块负责：

- 提供六维默认答案和有效范围。
- 将场景、预算和香味偏好映射为内部匹配条件。
- 计算单个酒款得分。
- 对明显超预算的候选执行现有预算过滤。
- 按得分排序并返回 Top 3。
- 计算用于展示的相对推荐指数。
- 校验和规范化传入的答案。

建议公开以下稳定接口：

```js
defaultAnswers()
normalizeAnswers(input)
scoreItem(item, answers)
recommend(items, answers, limit = 3)
```

推荐结果包含酒款对象、原始得分和相对推荐指数。相同数据和相同答案必须在 Web、小程序和 Node 测试中产生相同排序。

现有 `web/app.js` 保留 DOM 渲染、URL 参数、浏览器分享、Canvas 海报和埋点逻辑，但删除已经移动到共享模块的评分规则。此次抽取不得有意改变现有 Web 推荐结果。

## 数据生成

`data/baijiu.json` 是唯一权威数据源。小程序不在运行时请求静态 JSON，而是在构建时生成可通过 CommonJS 加载的 `wechat/miniprogram/data/baijiu.js`。

生成模块形式如下：

```js
module.exports = {
  meta: {},
  items: []
};
```

生成要求：

- 输出必须是确定性的，同一输入生成完全相同的内容。
- 不手工编辑生成文件。
- `scripts/build.sh` 同时更新 Web 数据副本和小程序数据模块。
- `scripts/check.sh` 验证源 JSON、Web 副本和小程序模块内容一致。
- 数据格式错误时构建立即失败，不生成部分文件或成功形态的空数据。

## 页面设计

### 首页 `pages/home`

- 展示 Wineer 品牌、产品说明和年龄提示。
- 用户点击“我已满 18 岁”后进入问答页。
- 年龄提示只是产品入口声明，不声明为实名年龄验证。

### 问答页 `pages/quiz`

- 展示六张滑块卡片，每项范围为 0–10、步长为 1。
- 滑动时实时更新数值和对应解释。
- 初始值来自共享核心的 `defaultAnswers()`。
- 点击“生成 Top 3 推荐”后，将规范化答案编码为短查询参数并导航到结果页。
- 不在页面间传递完整酒款列表或推荐结果对象。

### 结果页 `pages/result`

- 从页面参数恢复六维答案。
- 使用本地酒款模块和共享核心重新计算 Top 3。
- 展示推荐指数、酒名、品牌、香型、度数、参考价、价位档、产区、口感、推荐理由和避坑提示。
- 提供“重新选择”“转发给朋友”“生成分享海报”和“复制购买搜索词”。
- 购买搜索词格式采用“酒名 + 京东搜索”，复制成功后明确提示用户自行打开电商平台搜索。

### 酒款卡片 `components/wine-card`

卡片只负责展示单个推荐结果及触发购买词复制事件，不负责评分、导航、埋点或数据加载。

## 分享设计

### 微信原生转发

结果页实现页面分享回调。分享路径只携带六维答案，不携带酒款详情。接收方打开结果页后使用当前内置数据重新计算推荐。

分享标题使用第一名酒款和 Wineer 品牌组成，分享失败不影响结果页其他功能。

### 分享海报

海报使用小程序 Canvas 生成，包含：

- Wineer 品牌标题。
- 当前 Top 3 酒款名称和推荐指数。
- 简短免责声明，说明价格为参考价。
- 小程序分享提示。

生成成功后预览图片，并允许用户通过微信提供的保存流程保存。Canvas、临时文件或相册授权失败时显示明确原因和重试入口，不将失败报告为成功。

## 埋点

MVP 不接入远程服务。`utils/analytics.js` 将事件写入微信本地 Storage，最多保留最近 200 条。

事件名与 Web 保持一致：

- `start_quiz`
- `recommend`
- `share_click`
- `share_poster`
- `buy_click`
- `restart`

每条事件包含事件名、时间、页面路径和必要的非敏感业务参数。埋点失败不能阻塞核心流程，但不得使用空的 `catch`；开发环境记录明确的诊断信息。

## 状态与数据流

```text
首页确认年龄
  -> 问答页加载默认答案
  -> 用户调整六维滑块
  -> 规范化答案
  -> 导航到结果页并携带答案
  -> 加载本地酒款模块
  -> 调用 shared/recommender.js
  -> 渲染 Top 3
  -> 转发 / 海报 / 复制搜索词 / 重新选择
```

问答答案是推荐流程的唯一页面级业务状态。酒款数据是只读构建产物，推荐结果可以随时由答案重新计算，因此不需要全局状态库。

## 异常处理

- 页面参数缺失时使用默认答案。
- 超出 0–10、非整数或未知字段由 `normalizeAnswers()` 修正为安全值。
- 酒款数据缺失、不是数组或没有有效候选时显示错误状态和重试入口。
- 数据加载失败不得递归或循环调用推荐。
- 海报生成、剪贴板和分享相关失败使用 Toast 或对话框反馈。
- 用户拒绝相册权限时说明如何重新授权，不自动反复请求。
- 共享核心在酒款集合不是数组或任一酒款缺少评分必需字段时抛出 `RecommendationDataError`；页面捕获后展示数据错误状态，禁止以跳过记录或 `NaN` 排序的方式继续生成不完整推荐。

## 视觉与交互

- 延续现有 Web 的酒红、米色和卡片式移动端风格。
- 使用 WXML、WXSS 和微信原生组件重写，不复用 HTML 字符串。
- 所有主要操作提供点击反馈和禁用状态，避免重复生成推荐或海报。
- 滑块及按钮满足手机触控尺寸；长酒名、长推荐理由和较小屏幕不得溢出。
- 价格始终标注为市场参考价，不表达实时成交价格。

## 配置

- `wechat/project.config.json` 使用占位 AppID。
- `wechat/README.md` 说明如何替换 AppID、导入微信开发者工具和执行构建检查。
- 开发者个人设置不提交；如需要示例，使用 `project.private.config.json.example`。
- MVP 不读取 `.env`，也不包含服务端地址。

## 测试与质量门禁

### 共享核心单元测试

使用仓库现有 Node 运行时能力，不新增测试框架。测试至少覆盖：

- 默认答案完整且均处于 0–10。
- 答案规范化处理缺失值、字符串、越界值和非整数。
- 相同输入产生稳定排序。
- 返回数量不超过指定 limit。
- 有足够候选时返回三个不同酒款。
- 预算过滤延续现有行为。
- 典型画像的 Top 3 与抽取前 Web 算法一致。
- 空数据和非法酒款不会产生无限重试或 `NaN` 排序。

### 数据测试

- `data/baijiu.json` 通过现有语义校验。
- Web JSON 与源 JSON 完全一致。
- 小程序数据模块与源 JSON 深度一致。
- 生成脚本连续执行两次不产生差异。

### 小程序人工验收

- 首页可以进入问答页。
- 六个滑块均可更新数值和解释。
- 默认答案和边界答案可以生成结果。
- 结果页展示三个不同酒款及完整说明。
- 重新选择返回问答页。
- 分享路径可恢复相同答案和推荐。
- 海报可以生成、预览，并正确处理拒绝权限。
- 购买按钮复制预期搜索词。
- 缺失或非法分享参数不会导致白屏。

### CI

现有 CI 继续执行构建和检查。`scripts/check.sh` 增加共享核心测试、数据生成一致性检查和小程序 JavaScript 语法检查。

## 兼容与迁移

- Web 版本继续从 `web/` 独立部署。
- 小程序新增文件不得要求 Web 部署环境安装运行时依赖。
- 共享核心抽取前，使用固定典型画像记录当前 Web Top 3，作为行为回归基线。
- 抽取完成后，Web 与小程序均通过相同测试向量验证结果。
- 现有分享 URL 继续有效；小程序使用自己的页面查询参数格式。

## 实施边界

本设计对应一个实施计划，包含：

1. 为现有推荐行为建立回归测试。
2. 抽取共享推荐核心并接回 Web。
3. 增加小程序数据生成和一致性检查。
4. 创建原生小程序骨架与三个页面。
5. 实现结果卡片、分享、海报、复制搜索词和本地埋点。
6. 完善文档、CI 和人工验收。

任何登录、远程 API、商品库、联盟链接、支付、收藏或运营功能都应作为后续独立设计，不在 MVP 实施中顺带加入。

## 成功标准

- 微信开发者工具可从 `wineer/wechat/` 导入并运行项目。
- 小程序完成首页、问答和 Top 3 结果的完整主路径。
- Web 和小程序对相同数据及答案返回相同 Top 3。
- 数据只需在 `data/baijiu.json` 中维护一次。
- 构建和检查命令能够发现数据漂移、推荐回归和语法错误。
- 分享、海报、重新选择和复制购买搜索词均有明确成功或失败反馈。
- 现有 Web 功能和推荐结果不发生非预期变化。
